# LEARNING_06.md — настройки, сохранение оформления и настоящая пауза

Продолжение [LEARNING_05](LEARNING_05.md) для проекта [Boulder Dash](README.md). Исходники находятся в `/home/majorov/DEV/QML`.

## Результат этапа

Игра начинается с меню. Из него можно начать игру, открыть настройки или выйти. Во время игры Esc, P и кнопка «Пауза» открывают меню с продолжением и новой игрой. Настройки применяются сразу и сохраняются между запусками.

Настраиваются тема тайлов, вариант Персонажа, разрешение анимации и интервал кадров. Эти значения не меняют скорость симуляции. Экран настроек показывает анимированный предпросмотр, пока сама игра остаётся на паузе.

Учебные темы: `Q_PROPERTY` с `READ/WRITE/NOTIFY`, проверка значений в C++, `QSettings`, композиция QML-компонентов, состояние экранов, владение QObject, оставшееся время таймеров и проверка поведения через Qt Test.

## 1. Разделите ответственность

| Объект | За что отвечает |
|---|---|
| `GameSettings` | Допустимые настройки, сохранение и уведомления |
| `GameEngine` | Игровые правила, состояние паузы и таймеры восстановления Кирпичей |
| `main.qml` | Текущий экран, связь компонентов, клавиатура и таймер физики |
| `GameMenu.qml` | Отображение меню и сигналы пользовательских действий |
| `SettingsPanel.qml` | Управление настройками и визуальный предпросмотр |
| `MenuButton.qml` | Общая кнопка, подпись и сигнал `clicked` |

Исходники: [gamesettings.h](src/gamesettings.h), [gamesettings.cpp](src/gamesettings.cpp), [gameengine.h](src/gameengine.h), [gameengine.cpp](src/gameengine.cpp), [main.qml](qml/main.qml).

Настройки не принадлежат игровому движку: изменение темы не является ходом игрока. Меню не создаёт второй экземпляр GameEngine. Объект GameSettings создаётся в корне QML, а экран получает ссылку на него через типизированное свойство.

## 2. Полный цикл свойства C++ → QML → C++

В `GameSettings`:

```cpp
Q_PROPERTY(QString playerVariant
           READ playerVariant
           WRITE setPlayerVariant
           NOTIFY playerVariantChanged)
```

- `READ` — как QML получает текущее значение.
- `WRITE` — какой метод вызывается при присваивании из QML.
- `NOTIFY` — какой сигнал заставляет зависимые выражения пересчитаться.

В `main.cpp` класс регистрируется:

```cpp
qmlRegisterType<GameSettings>("BoulderDash", 1, 0, "GameSettings");
```

В `main.qml` есть один объект настроек и алиасы к его свойствам:

```qml
GameSettings { id: settings; objectName: "gameSettings" }
property alias playerVariant: settings.playerVariant
property alias tileTheme: settings.tileTheme
```

Алиас не копирует значение. Существующие кнопки оформления продолжают работать, но присваивание `root.playerVariant` теперь проходит через C++-сеттер и сохраняется.

Путь изменения:

```text
Нажатие «Герой»
  → новое значение playerVariant
  → GameSettings::setPlayerVariant()
  → проверка допустимости и сравнение с текущим значением
  → изменение поля
  → запись QSettings и sync()
  → emit playerVariantChanged()
  → новая подпись кнопки, картинка героя и предпросмотр
```

Повторное присваивание того же значения не пишет настройки и не испускает сигнал. Неизвестные темы и варианты отвергаются; интервал анимации принимается только в диапазоне 60–500 мс. UI предлагает 80, 140 и 220 мс.

Найдите в SettingsPanel присваивание темы. Проследите его до C++, диска и изменения изображения. Назовите места, которые отвечают за проверку значения, сохранение и обновление привязок.

## 3. Сохранение через QSettings

Имя организации приложения — `Majorov`, имя приложения — `BoulderDash`. На Linux при стандартном окружении используется файл:

```text
/home/majorov/.config/Majorov/BoulderDash.conf
```

При заданном `XDG_CONFIG_HOME` базовый каталог другой. Настройки оформления лежат в группе `appearance`; рекорд хранится отдельно, в прежнем ключе `highScore`.

| Ключ группы `appearance` | Значение по умолчанию |
|---|---|
| `tileTheme` | `classic` |
| `playerVariant` | `classic` |
| `animationsEnabled` | `true` |
| `animationInterval` | `140` |

Изменения сохраняются немедленно через `setValue()` и `sync()`. Загрузка проверяет значения: отсутствующие или некорректные заменяются в памяти значениями по умолчанию. «Сбросить оформление» записывает значения по умолчанию обратно на диск и не удаляет рекорд.

Сохранение оформления не означает сохранение прохождения: после перезапуска приложения уровень, позиция и очки текущей игры не восстанавливаются.

Для тестов предусмотрен конструктор с именем INI-файла:

```cpp
GameSettings settings(temporaryFileName);
```

Он позволяет проверить запись и повторное чтение в `QTemporaryDir`, не затрагивая пользовательский файл.

## 4. Состояние экранов и сигналы компонентов

В корне окна:

| `overlay` | Что видно | Состояние движка |
|---|---|---|
| `menu` | Начальное меню или меню паузы | Пауза |
| `settings` | Настройки | Пауза |
| пустая строка | Игра | Работа |

`sessionStarted` отличает начальное меню от паузы. `settingsReturn` хранит экран возврата: после настроек из меню игра остаётся на паузе, а после настроек из игрового поля — продолжается.

Меню сообщает намерение сигналом:

```qml
signal newGameRequested()
```

Корень решает, что сделать:

```qml
onNewGameRequested: root.newGame()
```

Так меню не зависит от внутреннего API движка. `newGame()` перезапускает прохождение, отмечает начало сессии и закрывает меню. Настройки оформления при этом сохраняются.

Esc и P открывают/закрывают паузу; в настройках возвращают на предыдущий экран. Выход из приложения доступен в меню. При возврате из меню или настроек фокус получает игровое поле.

Меню и настройки расположены выше игрового поля и уведомлений. Их MouseArea перехватывает клики, чтобы нажатие на фон не активировало кнопку под ним. Клавиатурный обработчик игрового поля не передаёт команды движения, пока виден overlay.

### Упражнение 6.3 — проверить возврат и фокус

Откройте настройки сначала из начального меню, потом из паузы и затем из игрового поля. Каждый раз закройте их кнопкой «Назад». Проверьте, куда вернулось приложение и работают ли стрелки после продолжения.

**Готово, если:** возврат сохраняет исходный смысл экрана, а для продолжения движения не требуется клик по полю.

## 5. Пауза должна работать в движке

Свойство:

```cpp
Q_PROPERTY(bool paused READ paused WRITE setPaused NOTIFY pausedChanged)
```

Связь с интерфейсом:

```qml
GameEngine {
    id: gameEngine
    paused: root.overlay !== ""
}
```

`movePlayer`, `dig`, `updateCrystals` и `updateGame` при паузе сразу возвращаются. Поэтому прямой вызов из другого компонента не обходит ограничение интерфейса.

Таймер физики в QML работает только при `!gameEngine.paused`. Его период — 250 мс. После продолжения начинается новый полный период; оставшаяся доля прежнего шага физики не сохраняется.

### Таймеры восстановления Кирпичей

У каждой выкопанной клетки свой одноразовый QTimer с исходным интервалом 15 секунд. Недостаточно остановить только периодический таймер физики: иначе Кирпич восстановится, пока игрок находится в меню.

При включении паузы:

1. Для каждого активного таймера движок читает `remainingTime()`.
2. Сохраняет значение по ключу клетки.
3. Останавливает таймер.

При продолжении запускает каждый таймер с сохранённым остатком. Если до паузы оставалось 4 секунды, после минуты в меню по-прежнему остаётся примерно 4 секунды.

Загрузка уровня удаляет старые таймеры и очищает сохранённые остатки. Новая игра из меню сохраняет паузу на время перезагрузки уровня, затем корневой экран продолжает игру. Это не даёт возобновить таймер из старой карты.

Остановленный QTimer остаётся QObject-потомком GameEngine: объект сохраняется для продолжения и удаляется вместе с владельцем. Для смены уровня используются `stop()` и `deleteLater()`; существующая механика уведомлений о Ключе и Сейфе сохранена.

### Упражнение 6.4 — найти неполную паузу

Объясните последствия двух ошибочных вариантов:

- Только отключить ввод, оставив QML Timer и C++ QTimer работающими.
- Остановить все таймеры, но при продолжении каждый раз запускать их с полными 15 секундами.

Затем выкопайте клетку, подождите несколько секунд, откройте меню на 20 секунд и продолжите игру.

**Готово, если:** время в меню не приближает восстановление Кирпича и не выдаёт новый полный срок после продолжения.

## 6. Анимация и симуляция — отдельные часы

`animationInterval` задаёт интервал кадров героя. Длительность пульсаций тайлов пропорциональна этому значению; период физики остаётся 250 мс, восстановление Кирпича — 15 секунд игрового времени вне паузы.

В игровом поле:

```qml
Player {
    animated: settings.animationsEnabled && !gameEngine.paused
    animationInterval: settings.animationInterval
}
```

При паузе перебор кадров и эффекты игрового поля останавливаются. Некоторые косметические анимации возвращаются к начальному виду; фаза каждого эффекта не сохраняется. Состояние движка при этом не меняется.

Предпросмотр в настройках использует `settings.animationsEnabled` без проверки игровой паузы: он намеренно продолжает показывать выбранную анимацию. Галерея также сохраняет самостоятельные настройки предпросмотра.

## 7. Тесты

На H2:

```bash
cd /home/majorov/DEV/QML
source build-qt5/env.sh
cmake --build build-qt5 --parallel 2
ctest --test-dir build-qt5 --output-on-failure
```

| Группа | Что проверяет этот этап |
|---|---|
| `gamesettings` | Значения по умолчанию, запись и чтение нового объекта, один сигнал на изменение, отказ от недопустимых значений, сброс без удаления рекорда |
| `gameengine` | Запрет ввода и физики на паузе, сохранение остатка таймера, повторные паузы с несколькими независимыми таймерами, очистку таймеров при новой игре |
| `tilelibrary` | Начальное меню, настоящие клики настроек, связь с героем, возврат на нужный экран, паузу и продолжение кнопками и Esc/P, повторное чтение сохранённых значений |

QML-проверки используют отдельный временный каталог настроек и программный рендеринг без видимого окна. Тесты не перезаписывают настройки пользователя.

Снимок настроек можно получить через UI-тест:

```bash
QML_SETTINGS_SCREENSHOT=/home/majorov/docs/QML-settings.png \
    ctest --test-dir build-qt5 -R tilelibrary --output-on-failure
```

Локальный снимок экрана настроек: `/home/majorov/docs/QML-settings.png`. Он не включён в репозиторий; команда выше позволяет создать его на H2.

### Почему важен остаток времени

Тест таймера сокращает интервал, ждёт часть срока, включает паузу дольше полного исходного интервала и убеждается, что клетка не изменилась. После продолжения проверяет оставшееся время и фактическое восстановление. Так проверяется поведение, а не наличие флага `paused`.

## 8. Самостоятельное расширение

Добавьте настройку размера визуального предпросмотра, не меняя размер логических клеток игры. Сначала определите диапазон и значение по умолчанию, затем свойство C++, сеттер с проверкой, QSettings-ключ, кнопку QML и тесты повторного чтения.

После этого можно расширить меню подтверждением новой игры или заменить строки экранов перечислением. Полное сохранение игрового прогресса остаётся следующим отдельным этапом.
