# LEARNING_10.md — успешная сборка, разрешение конфликтов Git и ресурсов Qt

Проект [Boulder Dash](../README.md), исходники `/home/majorov/DEV/QML`. Документ создан 6 ноября 2026 года по просьбе пользователя. Имя сохранено в указанном виде: `LEARNING_10.md`.

## 1. Исходная ситуация и проблема с обновлением экрана

Пользователь обновил файл `qml/levels/Level1.qml`, однако при запуске приложения через скрипт `bldr` отображался прежний экран. 

В ходе диагностики было выявлено, что проблема не связана с кэшем QML или логикой загрузки. Корень проблемы находился в системе контроля версий и целостности файлов сборки:
1. Проект находился в состоянии **detached HEAD** из-за незавершенного интерактивного `git rebase`.
2. В процессе разрешения конфликтов в файле `qml/main.qml` были допущены ошибки, а также остался неразрешенный конфликт в файле ресурсов `qml.qrc`.

## 2. Хронология разрешения Git-конфликтов

Процесс восстановления рабочего состояния включал несколько этапов:

1. **Завершение Rebase:** Находясь в detached HEAD, пользователь сделал коммит "обновил уровень 1". Было принято решение объединить его с предыдущим коммитом `"123"` (ветка main) для чистой истории.
2. **Исправление коммита:** Выполнены команды:
   ```bash
   git reset --soft HEAD~1
   git commit --amend
   git rebase --continue
   git push origin main
   ```
   Ветка `main` была успешно обновлена на удаленном репозитории (коммит `a06b365`).
3. **Конфликт в QML:** В файле `qml/main.qml` остались маркеры конфликта (`<<<<<<< HEAD`, `=======`, `>>>>>>> 8216fb8`). Требовалось вручную оставить нужные блоки (`Loader` и `GameEngine`) и удалить маркеры.

## 3. Критическая ошибка сборки: RCC Parse Error в qml.qrc

После исправления `main.qml` сборка продолжила падать. Скрипт `bldr` выдавал ошибку `Нет такого файла или каталога` для исполняемого файла, так как компиляция не доходила до конца.

Полный лог сборки выявил ошибку на этапе генерации ресурсов Qt:
```text
RCC Parse Error: '/home/majorov/DEV/QML/qml.qrc' Line: 15 Column: 2 [Unexpected '<'.]
```
**Причина:** В файл `qml.qrc` (формат XML) попал мусор — вероятно, маркеры конфликта Git или фрагмент QML-кода (символ `<`).

**Решение:** Пользователь открыл `qml.qrc`, удалил некорректные данные (строка 15) и восстановил валидную XML-структуру:
```xml
<RCC>
    <qresource prefix="/">
        <file alias="...">...</file>
        <!-- ... -->
    </qresource>
</RCC>
```

## 6. Правила работы с Git и сборкой на будущее

Для предотвращения подобных ситуаций зафиксированы следующие правила:

| Ситуация | Действие |
|---|---|
| **Незавершенный Rebase** | Сначала `git rebase --continue` (или `--abort`). Только после успешного завершения делать `git push` / `git pull`. |
| **Конфликты в файлах** | Искать маркеры `<<<<<<<`, `=======`, `>>>>>>>`. В `.qrc` файлах они недопустимы — это ломает `rcc`. |
| **Сборка упала** | Всегда читать лог до конца. Если написано `ninja: build stopped`, бинарник не создан. Запуск `bldr` вызовет ошибку "Нет такого файла". |
| **Изменения не видны** | Если QML собирается через `.qrc` (ресурсы), после изменения файлов нужно убедиться, что сборка прошла успешно, иначе старая версия останется в бинарнике. |
| **Кэш сборки** | При странных ошибках линковки или "залипании" сборки использовать `cmake --build build-qt5 --clean-first` или удалять папку `build-qt5`. |
