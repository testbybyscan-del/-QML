# LEARNING_08.md — исправление Level6 и запуск с выбранного уровня

## 1. Результат этапа

Шестая авторская карта полностью подключена и проходит проверку формата. Добавлен параметр `--level N`, который начинает новую сессию с выбранного уровня от 1 до 50. Для номера после последней подключённой авторской карты создаётся последовательность пейзажей с сохранением нумерации и seed. По уточнённому контракту выбранный номер N становится нижней границей тестовой сессии: переход на N−1 запрещён, переход вперёд после сбора обязательных Призов и возврат с последующих карт до N разрешены. «Новая игра» возвращает на 1 и снимает это ограничение.

При проверке этой возможности обнаружен прежний отказ генератора. Исправлено размещение Кристаллов и подходов к ним; строгая проверка карт сохранена. Добавлены тесты движка и отдельные проверки запуска настоящего исполняемого файла.

Это учебный разбор фактически внесённых изменений. Первоначальные результаты тестов ниже отмечены как исторические: они получены до уточнения нижней границы. Проверки загрузки и формата не доказывают прохождение карты с учётом всей физики.

## 3. Итоговое исправление Level6

Полная цепочка подключения теперь выглядит так:

```text
qml/levels/Level6.qml
  → запись levels/Level6.qml в qml.qrc
  → Levels.Level6 { id: level6 } в main.qml
  → level6.rows в initializeLevels(...)
  → проверка всех карт в GameEngine
  → authoredLevelCount == 6
```

В [qml.qrc](../qml.qrc) добавлен ресурс:

```xml
<file alias="levels/Level6.qml">qml/levels/Level6.qml</file>
```

В [main.qml](../qml/main.qml) создаётся объект и передаются шесть наборов строк:

```qml
Levels.Level6 { id: level6 }

// В существующем Component.onCompleted:
gameEngine.initializeLevels([
    level1.rows, level2.rows, level3.rows,
    level4.rows, level5.rows, level6.rows
])
```

В [Level6.qml](../qml/levels/Level6.qml) два пробела заменены точками. Вторая строка карты:

```text
#.C$C...C$C....C$C.#
```

Предпоследняя строка восстановлена без сдвига внутренней стены:

```text
#XxP.....#.......xX#
```

| Свойство | Итог |
|---|---|
| Размер | 13 строк × 20 клеток |
| Недопустимые символы | Отсутствуют |
| Старт `P` | Один, `(row=11, col=3)` |
| Левый выход `X` | `(11, 1)` |
| Правый выход `X` | `(11, 18)` |
| Обязательные Призы `$` | 10 |
| Кристаллы `C` | 35 |
| Комментарий | «Ручная карта 6» |

Координаты в таблице считаются с нуля. Число авторских карт вычисляется из принятого списка, отдельная константа 6 в движке не вводилась.

## 4. Команды запуска

Из каталога проекта на H2:

```bash
./build-qt5/run.sh --level 1
./build-qt5/run.sh --level 6
./build-qt5/run.sh --level 7
./build-qt5/run.sh --level 50
./build-qt5/run.sh --help
```

При настроенном окружении Qt можно запускать бинарный файл напрямую:

```bash
source build-qt5/env.sh
./build-qt5/boulderdash --level 6
```

| Вызов | Поведение |
|---|---|
| Без `--level` | Обычное начальное меню |
| `--level 1`…`--level 6` | Немедленный старт с соответствующей авторской карты |
| `--level 7` | Первый сгенерированный пейзаж |
| `--level 50` | Уровень 50; при шести авторских картах это пейзаж с seed 44 |
| `--tile-gallery` | Галерея тайлов |
| `--help` | Справка по параметрам |

Номера 7–50 сейчас не означают существование файлов Level7–Level50. Если позже подключить следующие авторские карты через ресурс, объект и список инициализации, они займут соответствующие номера. Один файл на диске по-прежнему не подключается автоматически.

Диапазон 1–50 ограничивает выбор стартового номера. Верхняя граница обычных переходов игры этим параметром не задаётся. При `--level N` нельзя уйти ниже N, но можно двигаться вперёд после сбора Призов и возвращаться до N. Команда «Новая игра» возвращает на первый уровень и снимает ограничение тестового старта.

Локальные `build-qt5/env.sh` и `run.sh` игнорируются Git. Существующий `run.sh` уже передаёт аргументы через `"$@"`, поэтому менять его не потребовалось. На другой машине нужно собрать приложение и настроить окружение Qt либо создать свои локальные обёртки.

## 5. Разбор аргументов в main.cpp

В [main.cpp](../main.cpp) используется `QCommandLineParser`. Он объявляет `--level`, `--tile-gallery` и справку. Для уровня проверяются преобразование в целое число, диапазон и отсутствие повторного параметра.

Ошибкой считаются:

```bash
./build-qt5/run.sh --level 0
./build-qt5/run.sh --level 51
./build-qt5/run.sh --level abc
./build-qt5/run.sh --level 1.5
./build-qt5/run.sh --level
./build-qt5/run.sh --level 1 --level 6
./build-qt5/run.sh --level 6 --tile-gallery
```

Такие вызовы завершаются с ненулевым кодом и диагностикой. Неожиданные позиционные аргументы также отклоняются.

Порядок успешного запуска:

1. Проверить аргументы.
2. Зарегистрировать C++-типы и загрузить корневой QML.
3. Дождаться синхронного завершения `engine.load()`: обработчик QML уже передаст авторские карты в движок.
4. Найти GameEngine и вызвать `startAtLevel(N)`.
5. Установить `sessionStarted = true` и вызвать существующий `resumeGame()` корневого окна.
6. Открыть игровое поле без меню и передать управление циклу событий.

При успехе выводится диагностическая строка, например:

```text
Начальный уровень: 6 Авторских уровней: 6
```

Важно выполнить выбор карты после инициализации: более раннее присваивание номера было бы перезаписано `initializeLevels()`. Вызов `newGame()` здесь тоже не подходит, поскольку он сбрасывает номер на 1.

## 6. Новый метод GameEngine::startAtLevel()

В [gameengine.h](../src/gameengine.h) добавлен публичный C++-метод:

```cpp
bool startAtLevel(int level);
```

Он не объявлен `Q_INVOKABLE`: запуском по аргументам командной строки управляет C++.

В [gameengine.cpp](../src/gameengine.cpp) метод сначала проверяет диапазон и наличие инициализированных карт. Затем во временном контейнере оставляет авторский набор и достраивает недостающие пейзажи с последовательными seed, начиная с 1.

Для старта с уровня 50 при шести авторских картах нужны 44 пейзажа. Номера 7–49 также существуют в памяти для последовательной нумерации и воспроизводимой генерации. Их наличие не даёт права уйти ниже выбранного стартового номера: при `--level 50` переход 50 → 49 запрещён. Предыдущие карты при прямом запуске ещё не пройдены, поэтому очки и предметы за них не начисляются.

Только после успешной подготовки всего маршрута новый набор заменяет рабочий. При ошибке аргумента, отсутствии инициализации или отказе генератора метод возвращает `false`; текущая сессия не заменяется частично подготовленной последовательностью. При таком отказе во время CLI-запуска приложение сообщает ошибку и завершается.

Успешный старт сбрасывает счёт, жизни до трёх, ключ, уведомления, снимки карт и игровые таймеры. Пауза сохраняется самим движком; при CLI-запуске её снимает `resumeGame()` через QML. Оформление и сохранённый рекорд не сбрасываются. `restartGame()` начинает обычную новую игру с уровня 1 и снимает ограничение тестового старта.

## 7. Почему пришлось исправлять генератор

Первые новые тесты авторских уровней 1 и 6 прошли. Проверки 7 и 50 упали: прежний `LandscapeGenerator::generate()` возвращал пустую карту для seed 1 и 44, исчерпав свои 32 попытки.

Диагностика:

```text
Landscape generation failed: "кристалл нельзя безопасно подтолкнуть"
```

Прежнее случайное размещение пяти Кристаллов над каждой платформой создавало соседние препятствия и изолированные клетки подхода. Особенно заметна проблема на верхней полке: потолок закрывает доступ сверху, а одна шахта не обеспечивает подход ко всем разделённым участкам.

В [landscapegenerator.cpp](../src/landscapegenerator.cpp) исправлено построение кандидата:

1. Для каждой платформы собираются допустимые позиции с кирпичной опорой.
2. Ограниченным перебором выбираются наборы из пяти несоседних позиций; один из наборов выбирается по seed.
3. Очищаются мешающие простенки рядом с Кристаллами.
4. Под пустыми соседями открываются дополнительные подходы через платформу и мешающий нижний простенок. Опоры самих предметов сохраняются.
5. При выборе места для Суперприза повторно проверяется фактическая кирпичная опора: старый список возможных клеток составлен до прорезания подходов и мог устареть.

Сохранены 20 Кристаллов — по пять на платформу, оба портала, нижний карман с Призом и задача копания. Строгая проверка кандидата не ослаблялась: она по-прежнему проверяет геометрию, опоры, достижимость наград и выходов, возможность подхода для толкания. Неподходящий кандидат отклоняется; число попыток остаётся 32.

Одинаковый seed воспроизводит карту при одной версии алгоритма. После изменения алгоритма вид карты для прежнего seed может измениться.

## 12. Уточнение: тестовая сессия не должна уходить ниже стартового уровня

После первоначальной реализации пользователь уточнил назначение `--level N`: это тестовый старт с нижней границей N. Ранее движок позволял вернуться на любую подготовленную карту; такой возврат оказался лишним для этого режима. Существование карты и разрешение перехода — отдельные условия.

Действующий контракт:

| Сценарий | Требуемое поведение |
|---|---|
| `--level 6`, левый выход на 6 | Остаться на 6; переход на 5 запрещён |
| `--level 6`, правый выход до сбора Призов | Остаться на 6 по обычным правилам |
| `--level 6`, правый выход после сбора Призов | Перейти на 7 |
| После такого перехода левый выход на 7 | Вернуться на 6 |
| Повторный левый выход на 6 | Остаться на 6 |
| `--level 50`, левый выход на 50 | Остаться на 50; прежний сценарий 50 → 49 запрещён |
| «Новая игра» после тестового старта | Уровень 1, тестовое ограничение снято |

Ограничение относится к разрешению перехода, поэтому левый выход может оставаться в данных и отображаться на карте. Подготовку промежуточных пейзажей сохраняем для последовательной нумерации и seed; доступ ниже N она не открывает. Обычные переходы вперёд сохраняют требование собрать обязательные Призы.

В движке хранится нижняя граница `m_firstPlayableLevel`. При успешном `startAtLevel(N)` она становится равной N. Вход в левый выход проверяет эту границу; защита перехода также находится в `switchToLevel()`. Неверные запросы не меняют границу, а `restartGame()` и успешная повторная `initializeLevels()` начинают с уровня 1.

Интерфейсу доступно свойство:

```cpp
Q_PROPERTY(bool canGoBack READ canGoBack NOTIFY levelChanged)
```

Его значение — `currentLevel > firstPlayableLevel`. QML использует `canGoBack` для `exitAvailable` левого выхода независимо от числа оставшихся Призов. Правый выход по-прежнему открывается после их сбора. Поэтому при нуле Призов на стартовом тестовом экране левый выход остаётся недоступным, а правый доступен. Подсказка отдельно сообщает запрет возврата ниже стартового уровня.

Выполнены проверки уточнения:

- На настоящих картах при старте с 6, 7 и 50 вход в левый выход не переводит на предыдущий номер.
- На контролируемом наборе карт проверен запрет 6 → 5; переход 6 → 7 до сбора Приза запрещён, после сбора разрешён.
- Возврат 7 → 6 восстанавливает снимок: обязательных Призов осталось 0, счёт 100, собранный Приз отсутствует. Повторный выход 6 → 7 работает, граница 6 сохраняется.
- Неверные запросы сохраняют границу; новая игра и повторная инициализация её снимают, обычный возврат 2 → 1 снова доступен.
- QML-тест при старте с 6 и нуле Призов проверяет оба выхода: левый `exitAvailable == false`, правый `true`; вызов `newGame()` возвращает на 1.

Первый вариант UI-теста не нашёл делегаты через `QObject::findChildren()`: дерево владения QObject не совпало с визуальным деревом элементов. Проверку исправили на обход `QQuickWindow::contentItem()` и `QQuickItem::childItems()`, после чего она проверила оба реальных выхода. Это пример того, почему поиск в модели объектов нужно соотносить с устройством QML-сцены.

Итоговый прогон после исправления UI-теста: **сборка успешна, 4/4 группы CTest прошли за 6,77 с**. Это отдельный результат нового контракта; историческое разрешение 50 → 49 из разделов 8–9 больше не действует. Полное ручное прохождение настоящего Level6 и всей последовательности 1–50 по-прежнему не заявляется.


## 13. Дополнение от 27 октября 2026 года: состав исправления тестового старта

Эта запись добавлена после проверки ограничения нижней границы. Ранее изложенный разбор и результаты первоначальной реализации сохранены; действующее поведение определяется уточнением в разделе 12.

### Причина уточнения

Пользователь сообщил, что возврат ниже уровня, указанного флагом, открывает предыдущие карты в исходном состоянии и мешает проверке дальнейшего продвижения с выбранного экрана. Поэтому для тестового запуска установлена нижняя граница доступного маршрута. Описанный пользователем сбой полного прохождения отдельно не воспроизводился; автоматические проверки подтверждают новый контракт переходов и сохранение состояния тестовой карты.

Например, команда:

```bash
./build-qt5/run.sh --level 6
```

означает, что прохождение этой сессии начинается с экрана 6. Левый выход на нём не переводит на 5. После сбора всех обязательных Призов правый выход переводит на 7; с экрана 7 можно вернуться на 6. Вернувшись, игрок сохраняет собранные Призы и может снова выйти вперёд. Уход ниже 6 остаётся запрещённым до новой игры.

### Какие проверки подтверждают результат

Тест `testStartBlocksEarlierMapsAndPreservesForwardProgress()` проверяет цепочку на контролируемых картах: запрет 6 → 5, запрет правого перехода до сбора Приза, сбор Приза, переход 6 → 7, возврат 7 → 6 и повторный переход вперёд. После возврата остаются 0 обязательных Призов и 100 очков, клетка собранного Приза пуста.

Тест `testStartBoundarySurvivesInvalidRequestsAndResetsWithNewSession()` проверяет сохранение границы после неверных номеров и её сброс через `restartGame()` и `initializeLevels()`. Отдельная проверка настоящих карт охватывает блокировку левого перехода при старте с 6, 7 и 50.

UI-тест `testStartKeepsLeftExitUnavailableAfterCollectingPrizes()` использует карту без оставшихся обязательных Призов: левый выход недоступен, правый доступен. Таким образом, условие «все Призы собраны» открывает путь вперёд и не снимает нижнюю границу.

Подтверждённый прогон для этого исправления: `cmake --build build-qt5 --parallel 2` и `ctest --test-dir build-qt5 --output-on-failure` после подключения `build-qt5/env.sh`; сборка успешна, **4/4 группы тестов прошли за 6,77 с**. Это тот же прогон, который приведён в разделе 12, а не дополнительное испытание. Проверка `git diff --check` также прошла.

Текущая запись документирует уже проверенное изменение. Полное ручное прохождение настоящих карт не выполнялось; успешные проверки переходов на контролируемом наборе не объявляются доказательством проходимости Level6.
