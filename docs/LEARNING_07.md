# LEARNING_07.md — разбор ошибок подключения Level6.qml

Продолжение [LEARNING_06](LEARNING_06.md). Проект: [Boulder Dash](../README.md), исходники — `/home/majorov/DEV/QML`.

Этот материал разбирает реально обнаруженное состояние проекта. Здесь приведены диагностика и предлагаемые исправления. При подготовке документа `Level6.qml`, ресурсы, список уровней и тесты игры не изменялись. Примеры исправлений ниже нужно применять отдельно.

## 1. Что заметили и какой вопрос задали

При обновлении `strctr.txt` обнаружилось, что на диске есть `qml/levels/Level6.qml`, но приложение использует только пять авторских уровней.

Первый вопрос: «Почему шестой уровень не появляется?» Возможные причины различаются:

- файла нет в ресурсах;
- QML не создаёт объект уровня;
- данные объекта не переданы движку;
- движок отвергает карту;
- уровень загрузился, но вход или выход не соответствует правилам перехода.

Не следует сразу менять генератор, увеличивать число уровней константой или рисовать на экране номер 6. Сначала нужно проследить путь данных от файла до GameEngine.

## 3. Как карта должна попасть в игру

```text
Файл qml/levels/Level6.qml
  → запись в qml.qrc
  → встроенный ресурс qrc:/levels/Level6.qml
  → объект Levels.Level6 в main.qml
  → свойство level6.rows
  → элемент списка initializeLevels(...)
  → проверка карты в C++
  → m_levels и m_authoredLevelCount
  → переход на авторский уровень 6
```

Каждая стрелка означает отдельное условие. Наличие файла на диске подтверждает только первый шаг.

### Слой 1: ресурс приложения

Корневой QML загружается из `qrc:/main.qml`. Импорт `import "levels" as Levels` ищет компоненты относительно ресурсного каталога. Он не означает автоматическое подключение всех QML-файлов из исходной папки на диске.

В [`qml.qrc`](../qml.qrc) перечислены Level1–Level5. Встроенного Level6 нет.

CMake включает ресурсный файл через `qt5_add_resources(...)`. Поэтому при таком способе упаковки одного создания файла в каталоге недостаточно.

### Слой 2: создание объекта QML

В [`qml/main.qml`](../qml/main.qml) создаются:

```qml
Levels.Level1 { id: level1 }
Levels.Level2 { id: level2 }
Levels.Level3 { id: level3 }
Levels.Level4 { id: level4 }
Levels.Level5 { id: level5 }
```

В ресурсе могут лежать десятки компонентов, но объекты из них не возникают сами собой. Нужно создать Level6, чтобы получить его `rows`.

### Слой 3: передача данных в C++

В обработчике `Component.onCompleted` сейчас передаются только пять массивов:

```qml
gameEngine.initializeLevels([
    level1.rows, level2.rows, level3.rows, level4.rows, level5.rows
])
```

Даже созданный объект Level6 останется неиспользуемым, если его данные отсутствуют в списке.

### Слой 4: принятие данных движком

В [`GameEngine::initializeLevels()`](../src/gameengine.cpp) входной список проверяется и складывается во временный контейнер. Только после успешной проверки всех карт выполняется:

```cpp
m_levels = levels;
m_authoredLevelCount = levels.size();
```

Количество авторских уровней вычисляется из принятого списка. Его не нужно отдельно задавать числом 6.

### Почему после пятого уровня появляется пейзаж

В `movePlayer()` при входе в правый выход после сбора обязательных Призов вычисляется следующий номер. Если такая карта уже есть в `m_levels`, вызывается `switchToLevel()`. Если её нет — `generateNextLandscape()` добавляет сгенерированную карту.

Пять переданных карт → после пятой карты включается генератор. Шесть переданных карт → сначала загружается шестая, а генератор понадобится после последней доступной карты.

Сам номер `currentLevel == 6` не доказывает, что открыт файл Level6: это может быть первый сгенерированный пейзаж. Сверяйте `authoredLevelCount`, содержимое карты и заголовок HUD.

## 4. Ошибка данных: пробелы внутри строк карты

Вторая строка Level6:

```text
# C$C...C$C....C$C #
```

В ней два пробела: строка 2, столбцы 2 и 19 при счёте с единицы. В координатах C++ это `row = 1`, `col = 1` и `col = 18`.

Текущий алфавит карты:

```cpp
const QString validTiles = QStringLiteral("#.$PXCxSH-EKB*");
```

Обычного пробела в нём нет. Визуально пробел похож на пустую клетку, но движок обозначает пустую клетку точкой `.`.

QML-синтаксис при этом корректен: пробел внутри кавычек является допустимым символом строки. Ошибка появляется на уровне правил игровых данных, когда C++ проверяет содержимое `rows`.

### Что произойдёт, если исправить только подключение

После добавления ресурса, объекта и `level6.rows` движок дойдёт до пробела, вызовет предупреждение:

```text
Неизвестный символ карты в QML-уровне:
```

и завершит `initializeLevels()` через `return`.

Проверка не пропускает только плохую карту и не принимает первые пять. Она отклоняет новый набор целиком до присваивания `m_levels`.

- У нового GameEngine авторских уровней останется 0, размеры поля — 0.
- У уже инициализированного движка прежние данные не будут заменены новым частичным набором.
- Успешное создание корневого окна QML не означает успешной инициализации игры.

Поэтому после неполного исправления можно получить запускающееся приложение с меню, но без корректно загруженного игрового поля. Это ожидаемое следствие проверки данных, а не доказательство поломки отрисовки.

### Правильная минимальная правка

Если оба пробела означали обычное пустое место, заменить их на точки:

```text
#.C$C...C$C....C$C.#
```

Длина строки останется 20.

Не удаляйте пробелы: строка станет короче на две клетки, и проверка одинаковой ширины отклонит карту. `trimmed()` также не исправит пробелы между символами внутри строки.

Не добавляйте пробел в список допустимых символов только для подавления ошибки. Допуск символа — изменение формата карты, которое нужно согласовать с физикой. Например, проверка возможности толкнуть Кристалл ожидает в клетке назначения именно `.`. Символ, который выглядит пустым, не обязательно одинаково работает во всех ветках движка.

## 5. Ошибка игрового маршрута: нет левого выхода

Предпоследняя строка Level6:

```text
#..P.....#.......xX#
```

Справа есть выход `X`, слева — две точки. Для возврата движок проверяет одновременно:

```cpp
m_playerY == m_rows - 2
m_playerX == 1
tileAt(m_playerY, m_playerX) == 'X'
m_currentLevel > 1
```

В нужной левой клетке находится `.`, поэтому переход назад не произойдёт. Даже после исправления ресурсов и пробелов карта может загрузиться, но обратный маршрут останется нарушенным.

Это не ошибка текущей синтаксической проверки: она требует хотя бы один `X`, а не наличие выходов в обоих ожидаемых местах.

### Предлагаемая правка для обычного шестого уровня

По образцу других последующих уровней:

```text
#XxP.....#.......xX#
```

Ширина остаётся 20, старт P сохраняется, справа остаётся прежний выход. Слева добавляется `X`, соседняя клетка обозначается `x`, как в других авторских картах.

`X` и `x` различаются. `X` — выход; `x` отображается как пустая клетка и не запускает переход. Замена всех строчных `x` на `X` не является исправлением.

Если отсутствие возврата задумано автором уровня, это нужно явно зафиксировать как правило конкретной карты и отразить в подсказках. История текущего файла такого намерения не подтверждает.

## 6. Почему прежние проверки были зелёными

| Проверка | Почему не нашла проблему |
|---|---|
| Компиляция C++ | Не обязана проверять существование неиспользуемого QML-компонента |
| Сборка ресурсов | Упаковывает перечисленные файлы; отсутствие неперечисленного Level6 не считается ошибкой |
| Запуск игры | Загружает только пять объявленных авторских карт |
| Валидация карты | Не выполняется для карты, не переданной движку |
| Тесты существующих уровней | Проверяют только перечисленные в них URL и сценарии |
| UI-тест открытия окна | Само по себе не доказывает ожидаемое число авторских карт |

В `test_gameengine.cpp` есть целевые проверки карт Level1, Level3, Level4 и Level5. Тесты не устанавливают требование «все файлы LevelN.qml обязательно подключены» и не проверяют ресурс Level6. Поэтому зелёный результат совместим с отсутствием шестого уровня.

Это пробел в проверке интеграции. Он не означает, что все существующие тесты бесполезны: они проверяли другие требования.

Ещё одна ошибка сопровождения — комментарий «Ручная карта 1» внутри Level6. Он не влияет на выполнение, но мешает чтению и показывает, почему при копировании файла нужно проверять не только код, но и описание.

## 7. Диагностика без изменения игры

Выполняйте из каталога проекта:

```bash

rg -n 'Level6|initializeLevels' qml.qrc qml/main.qml
cat qml/levels/Level6.qml
git show --stat 95abc28
```

Проверка размеров и символов текущего простого формата файла:

```bash
python3 - <<'PY'
from pathlib import Path
import re

source = Path('qml/levels/Level6.qml').read_text()
rows = re.findall(r'^\s*"([^"]*)"', source, re.M)
allowed = set('#.$PXCxSH-EKB*')
print('Строк:', len(rows))
print('Ширины:', sorted(set(map(len, rows))))
for row, text in enumerate(rows, start=1):
    for col, symbol in enumerate(text, start=1):
        if symbol not in allowed:
            print(f'Строка {row}, столбец {col}: {symbol!r}, U+{ord(symbol):04X}')
for symbol in ['P', 'X', '$', 'C']:
    print(symbol, sum(text.count(symbol) for text in rows))
PY
```

Это вспомогательная проверка конкретного массива строк, а не универсальный парсер QML: она не вычисляет JavaScript, выражения, экранирование и динамически созданные строки. Проверка через настоящий QQmlEngine и GameEngine остаётся необходимой.

Диагностируйте сверху вниз: существование ресурса → создание объекта → получение rows → принятие набора движком → игровой переход. Так легче отличить проблему упаковки от ошибки содержимого.

## 8. Варианты исправления

### Вариант A — подключить шестой уровень полностью

Для текущей задачи это наиболее прямой путь.

1. Исправить два пробела на точки, сохранив ширину.
2. Добавить левый выход, если шестой уровень должен поддерживать обычный возврат.
3. Исправить комментарий на «Ручная карта 6».
4. Добавить ресурс:

```xml
<file alias="levels/Level6.qml">qml/levels/Level6.qml</file>
```

5. Создать объект рядом с остальными уровнями:

```qml
Levels.Level6 { id: level6 }
```

6. Передать данные в нужном порядке:

```qml
gameEngine.initializeLevels([
    level1.rows, level2.rows, level3.rows,
    level4.rows, level5.rows, level6.rows
])
```

7. Добавить проверки ресурса, принятия карты, состава набора и переходов.
8. Обновить README и `strctr.txt`: авторских уровней стало шесть.
9. Собрать, выполнить CTest и проверить карту в игре.

Не увеличивайте `m_authoredLevelCount` вручную: его источником должен оставаться фактически принятый список.

### Вариант B — оставить карту экспериментальной

Если карта ещё не готова, её можно оставить вне игры, но состояние должно быть явным:

- переместить в отдельный каталог экспериментальных карт;
- описать, что она не включена в последовательность прохождения;
- не заявлять шесть доступных авторских уровней;
- проверять экспериментальную карту отдельно, прежде чем переносить в игровой набор.

Одна запись в `strctr.txt` объясняет факт, но сама по себе не предотвращает повторение ошибки.

### Вариант C — усилить каталог и валидацию

После минимального исправления можно уменьшить число независимых мест регистрации:

- завести явный каталог подключённых авторских карт с порядком прохождения;
- использовать его для загрузки и проверки числа карт;
- добавить проверку соответствия каталога ресурсам;
- помечать экспериментальные файлы отдельно, чтобы не требовать подключения каждой заготовки;
- возвращать результат и подробности ошибки инициализации в интерфейс.

Даже общий каталог не отменяет упаковку ресурсов. При сборке с `qrc:/` перечисленные в каталоге компоненты должны попасть в `qml.qrc` или в ресурс, который генерируется из того же каталога.

Автоматический сбор всех `Level*.qml` по маске требует осторожности: черновик может неожиданно стать игровым уровнем, а строковая сортировка поставит Level10 перед Level2. Нужны явный порядок и явный статус карты.

## 9. Какие тесты добавить

Ниже приведены предлагаемые изменения тестов. Они не добавлены в проект в рамках написания этого документа. Не копируйте все фрагменты в произвольное место: первые используют существующие функции-помощники и класс GameEngineTest из `tests/test_gameengine.cpp`.

### 9.1. Отдельно проверить загрузку и принятие Level6

Предложение для нового слота GameEngineTest после исправления карты и ресурса:

```cpp
void levelSixLoadsAndIsAccepted()
{
    QQmlEngine engine;
    const auto rows = loadQmlLevel(engine, QStringLiteral("qrc:/levels/Level6.qml"));
    QVERIFY2(!rows.isEmpty(), "Level6 отсутствует в ресурсах или не создаётся");

    GameEngine game;
    initialize(game, rows);
    QCOMPARE(game.authoredLevelCount(), 1); // В этом тесте передана одна карта.
    QCOMPARE(game.rows(), 13);
    QCOMPARE(game.columns(), 20);
    QCOMPARE(game.prizesLeft(), 10);
}
```

Здесь две разные гарантии. Непустые `rows` доказывают загрузку QML. Значения GameEngine доказывают, что он принял карту. Одной проверки `!rows.isEmpty()` недостаточно: массив может содержать пробелы или несколько стартов.

### 9.2. Проверить отказ от плохого символа

Предложение для отдельного слота; добавьте `#include <QRegularExpression>`:

```cpp
void invalidSymbolDoesNotReplaceLoadedLevels()
{
    GameEngine game;
    const auto valid = emptyLevel();
    initialize(game, valid);
    QCOMPARE(game.authoredLevelCount(), 1);
    const int oldRows = game.rows();
    const int oldColumns = game.columns();
    const int oldX = game.playerX();
    const int oldY = game.playerY();

    auto invalid = valid;
    setCell(invalid, 1, 1, QLatin1Char(' '));
    QVariantList proposed;
    proposed.append(QVariant::fromValue(asVariantRows(valid)));
    proposed.append(QVariant::fromValue(asVariantRows(invalid)));

    QTest::ignoreMessage(QtWarningMsg,
        QRegularExpression(QStringLiteral("Неизвестный символ карты.*")));
    game.initializeLevels(proposed);

    QCOMPARE(game.authoredLevelCount(), 1);
    QCOMPARE(game.rows(), oldRows);
    QCOMPARE(game.columns(), oldColumns);
    QCOMPARE(game.playerX(), oldX);
    QCOMPARE(game.playerY(), oldY);
}
```

Этот тест фиксирует договор: неудачная проверка всего нового набора не должна частично заменить уже работающий. Отдельный случай нужен для свежего GameEngine: после отказа его число карт и размеры должны оставаться нулевыми.

### 9.3. Проверить реальный набор главного окна

В UI-тесте после загрузки `qrc:/main.qml` найдите GameEngine и проверьте:

```cpp
QCOMPARE(game->authoredLevelCount(), 6);
```

Требование «шесть авторских карт» должно быть явно подтверждено. Если тест сам получает ожидаемое число из того же случайно укороченного списка, он может повторить ошибку приложения.

При дальнейшем переходе к каталогу можно сравнивать фактический набор с отдельно проверяемым контрактом релиза или утверждённым перечнем уровней.

### 9.4. Проверить переходы отдельно от сложности карты

Нужны сценарии:

- из пятой авторской карты переход ведёт на шестую без создания пейзажа;
- из шестой карты левый выход возвращает на пятую;
- после последней авторской карты правый выход запускает генератор;
- сохраняется состояние предыдущей карты при возврате.

Для проверки механики используйте небольшие контролируемые карты с известными позициями и Призами. Затем отдельно проверьте состав настоящего набора. Не делайте тест интеграции зависимым от длинного ручного маршрута среди 35 падающих Кристаллов.

`currentLevel == 6` само по себе недостаточно. Для перехода 5 → 6 проверьте, что `authoredLevelCount == 6` и загружены ожидаемые данные шестой авторской карты. При переходе к генератору авторское число остаётся 6, а текущий номер становится 7.

### 9.5. Проверить формальные свойства всех авторских карт

Добавьте проверку набора целиком, а не только отдельных выбранных файлов:

- известный ресурс загружается;
- все строки одинаковой ожидаемой ширины;
- символы входят в алфавит;
- старт ровно один;
- правый выход находится в ожидаемой клетке;
- на последующих обычных уровнях есть левый выход;
- количество обязательных Призов соответствует карте.

Условие «хотя бы один X» слабее реального контракта переходов. Усиливать его нужно осознанно: если будут уровни с иными правилами порталов, формат карты должен уметь описывать эти правила.

## 10. Формальная валидность не доказывает проходимость

После исправления пробелов карта пройдёт текущие проверки размеров, алфавита, числа стартов и наличия выхода. Это не доказывает, что игрок может собрать все 10 обязательных Призов и добраться до выхода.

Падение и толкание Кристаллов, копание, таймеры и маршрут могут сделать уровень сложным или непроходимым. Без проверки нельзя утверждать ни его проходимость, ни непроходимость.

Разделяйте доказательства:

| Результат | Что он подтверждает |
|---|---|
| CMake собрал приложение | Сборочная конфигурация и компиляция сработали |
| QQmlEngine создал карту | Ресурс и QML-компонент доступны |
| GameEngine принял rows | Текущие проверки формата пройдены |
| В главном окне шесть авторских карт | Набор передан движку полностью |
| Контролируемые переходы прошли | Механика последовательности и возврата работает |
| Настоящий Level6 пройден | Подтверждён конкретный маршрут в проверенных условиях |

Не заменяйте последнее утверждение первым.

## 11. План проверки предлагаемого исправления

На H2 после внесения изменений в игру:

```bash
cd /home/majorov/DEV/QML
source build-qt5/env.sh
cmake --build build-qt5 --parallel 2
ctest --test-dir build-qt5 --output-on-failure
git diff --check
```

Затем запустите `boulderdash` и отдельно проверьте:

1. Игра запускается без QML-ошибок и предупреждений валидации.
2. GameEngine получил шесть авторских карт.
3. Пятая карта переходит именно в авторскую шестую.
4. На шестой карте видны ожидаемые объекты и работают оба направления перехода.
5. После шестой появляется первый сгенерированный пейзаж.
6. Новая игра возвращает в начало, сохраняя оформление и не сохраняя таймеры старой карты.
7. Найден реальный маршрут сбора обязательных Призов; если нет — результат пока не заявляется.

Сборка после изменения ресурсов обязательна: старый бинарный файл может продолжать содержать старый список встроенных QML, даже когда исходники на диске уже исправлены.

## 12. Улучшение диагностики как отдельная учебная задача

Сейчас `initializeLevels()` возвращает `void`, а предупреждение о неизвестном символе не содержит номера карты и координат. В интерфейс не передаётся явное состояние ошибки загрузки.

Следующее улучшение можно спроектировать так:

- выделить проверку карты в отдельную функцию;
- возвращать структурированный результат с номером уровня, строкой, столбцом и символом;
- сообщать об ошибке через свойство и сигнал или возвращаемый результат;
- показывать понятное сообщение в меню и не предлагать начать пустой уровень;
- сохранять прежнее состояние при отказе от нового набора.

Например, полезное сообщение:

```text
Авторский уровень 6: строка 2, столбец 2 — пробел U+0020.
Для пустой клетки используйте точку '.'.
```

Это предлагаемый контракт, а не существующее поведение. При реализации сначала нужно определить формат ошибки и ответственность слоёв, затем изменить C++ и интерфейс и добавить тесты.

## 13. Упражнения по разбору ошибок

### 7.1. Составить таблицу гипотез

До исправления перечислите причины отсутствия карты и укажите проверку для каждой. Сопоставьте гипотезы с найденными фактами, не выдавая предположения об авторе файла за доказанный факт.

### 7.2. Проверить частичные исправления

В отдельной экспериментальной ветке меняйте по одному условию: ресурс, создание объекта, список rows, содержимое карты. Для каждого состояния запишите, какой слой теперь работает и какой ещё нет.

Не проводите эксперимент на единственной рабочей копии без сохранения изменений. Не используйте разрушительные команды сброса ради очистки эксперимента.

### 7.3. Написать тест до исправления

Добавьте проверку ожидаемых шести авторских карт в UI. Убедитесь, что она падает на текущем состоянии. Затем исправьте подключение и данные и проверьте, что тест стал зелёным. Отдельно проверьте возврат с шестого уровня.

### 7.4. Улучшить сообщение об ошибке

Спроектируйте результат валидации с координатами. Сначала напишите тест на конкретную плохую строку, затем реализуйте сообщение в C++ и его отображение в QML.

### 7.5. Объяснить случай своими словами

Ответьте письменно:

- Почему файла на диске недостаточно для загрузки из qrc?
- Почему корректная строка QML может быть неправильной игровой картой?
- Почему сборка и старые тесты прошли?
- Почему генератор не является причиной отсутствия авторского Level6?
- Почему замена пробелов решает только одну часть проблемы?
- Почему успешно загруженную карту ещё нужно проверить на проходимость?

**Критерий понимания:** вы можете восстановить цепочку данных, назвать отдельную проверку для каждого слоя и отличить исправление причины от подавления её проявлений.
